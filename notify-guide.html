Событие в GitHub становится сообщением в Telegram

Один файл решает, на что репозиторий реагирует и что именно попадёт в чат, канал или тему форума. Каждое событие теперь приходит с заголовком и рабочей ссылкой — без исключений.

01

Какие события подключены

Блок on: перечисляет все триггеры разом — воркфлоу запускается на каждый из них. Для каждого события есть своя пара «заголовок + ссылка» — она собирается на первом шаге воркфлоу (Build message) и не зависит от того, есть ли в GitHub-выражениях нужное поле.

02

Из чего складывается текст уведомления

Теперь это два шага, а не один. Первый разбирает JSON события через jq и решает, что стало заголовком и ссылкой для конкретного типа события. Второй — собирает готовый текст и отправляет его на webhook бота.

— шаг 1: Build message — case "$EVENT_NAME" in push) TITLE=$(jqval '.head_commit.message') LINK=$(jqval '.head_commit.url // .compare') ;; fork) TITLE=$(jqval '.forkee.full_name') LINK=$(jqval '.forkee.html_url') ;; # ...ещё 18 веток case — по одной на каждое событие esac — шаг 2: Send notification — TEXT=$(jq -n \ --arg event "$EVENT_NAME" --arg repo "$REPO" \ --arg title "$TITLE" --arg link "$LINK" \ -r '"🚀 *" + $event + "* in `" + $repo + "`\n\n" + $title + "\n\n[View on GitHub](" + $link + ")"') curl -X POST https://corerudo.larten.ru/webhook \ -d "$PAYLOAD"
jqval()
Маленькая функция-обёртка: читает файл события ($GITHUB_EVENT_PATH) через jq и достаёт нужное поле. Если поля нет — возвращает пустую строку, а не падает с ошибкой.
case по событию
На каждый тип события — своя ветка: откуда брать TITLE и LINK. Ветка ничего не находит — сработает запасной вариант в конце (TITLE="$EVENT_NAME", LINK=$REPO_URL), так что пустых уведомлений больше не бывает.
почему jq, а не ||
В выражениях GitHub Actions (${{ ... }}) нельзя нормально достать элемент массива — например, pages[0] для вики. jq — полноценный язык для JSON, ему такие вещи по силам, плюс он безопасно экранирует кавычки и переносы строк.
сборка текста
jq -n собирает итоговую строку и сразу весь JSON-пейлоад для запроса. Кавычки внутри заголовка коммита или PR больше не ломают запрос, как это было в старой версии на прямой подстановке в JSON-строку.
03

Как подстроить под себя

Три задачи, которые обычно и нужны.

Не нужны все события — только часть
Удалите лишние строки из блока on: в начале файла. Например, чтобы не слышать про звёзды и форки — уберите строки watch: и fork:. Воркфлоу перестанет запускаться на эти события вовсе.
Хочу другой текст для конкретного события
Найдите нужную ветку в блоке case "$EVENT_NAME" in ... esac первого шага и поменяйте, что попадает в TITLE и LINK. Например, для watch сейчас:
watch) WHO=$(jqval '.sender.login') TITLE="⭐ ${WHO} поставил звезду" LINK=$(jqval '.sender.html_url') ;;
Меняете строку с TITLE= на свою — формат сообщения полностью в ваших руках.
Появилось новое событие, которого нет в списке
Добавьте его в блок on: вверху файла, а затем — новую ветку в case первого шага по образцу остальных. Какие поля доступны для конкретного события — смотрите в официальной документации GitHub, раздел Webhook events and payloads, нужное событие.
🧵
Если чат — форум с темами, для доставки в конкретную тему нужен секрет NOTIFY_THREAD_ID (бот выдаёт его вместе с chat id по команде /getid, если писать её внутри темы). В текущей версии воркфлоу thread id в запрос не передаётся — это отдельная доработка шага Send notification, если она вам нужна, дайте знать.
